# 八个核心学习页统一设计规格

**日期：** 2026-08-31  
**状态：** 已完成对话设计确认，等待书面规格复核  
**参考页面：** `/shenlun/framework/`

## 1. 背景与目标

站点的八个核心学习页已经共享顶部学习导航和部分 Hero 坐标规则，但页面骨架、目录关系、正文表面、卡片节奏和交互方式仍不一致。现有 `learning-hero-standard.css` 主要用跨页面选择器和定位规则把首屏元素拉到相同坐标；`/shenlun/framework/` 则拥有更完整的纸张讲义结构、左侧目录以及 Hero 入口变形到目录项的共享元素动画。

本轮把以下八页统一为一个视觉与交互系统：

- 申论：`/shenlun/framework/`、`/shenlun/questions/`、`/shenlun/writing/`、`/shenlun/videos/`
- 面试：`/interview/methods/`、`/interview/questions/`、`/interview/expression/`、`/interview/videos/`

目标不是把八页改成相同内容，而是让它们共享同一套学习页骨架：顶部导航、纸张式 Hero、四格本页章节入口、左侧粘性目录、右侧正文表面、卡片规则、响应式结构、页脚关系和进入目录的过渡动画。

## 2. 已确认的产品决策

1. 只改八个核心学习页；首页和其他 27 个静态路由不在本轮范围内。
2. 八页统一布局、组件、字体、间距和纸张风格。
3. 申论保留蓝色主题，面试保留棕色主题；中性纸色、墨色、边框、排版和间距统一。
4. 保留每页现有内容、链接、筛选和数据加载方式，不把题库、素材库或视频页强制改成长篇讲义。
5. 保留并推广 `/shenlun/framework/` 已有的 Hero 入口到左侧目录的共享元素过渡。
6. 桌面、移动端、键盘操作、减少动态效果和不支持 View Transitions 的浏览器都必须可用。
7. 不新增依赖，不推送，不部署。

## 3. 方案比较

### 采用：共享讲义骨架系统

提取参考页中可复用的结构、令牌和交互，由各路由继续提供自己的正文内容。该方案能同时获得视觉一致性、长期可维护性和清晰的负载边界。

### 不采用：仅用 CSS 覆盖现有页面

短期修改量较小，但当前跨页面定位 CSS 已证明容易堆叠选择器和 `!important`，不同 DOM 结构仍会继续漂移。

### 不采用：复制 framework 页面结构和专属样式

第一眼最像参考页，但会复制大量 JSX/CSS，并把讲义语义强加给题目、写作入口和视频内容，还可能破坏现有 specialist CSS 与数据加载边界。

## 4. 视觉系统

### 4.1 统一页面顺序

每页按照同一顺序呈现：

1. 学科主题线和 `LearningTopNav`
2. 纸张/编辑部风格 Hero
3. 英文眉题、超大中文标题、说明文字和阅卷章
4. 四格“本页章节”入口
5. 学科强调线
6. 左侧粘性目录 + 右侧正文阅读表面
7. 统一关系的学习页页脚

`LearningTopNav` 继续承担八个路由之间的跨页导航。Hero 四格入口只负责当前页面内的四个宏观章节，不再混用跨页链接和本页目录语义。

### 4.2 共用令牌

共享层只定义以下中性规则：

- 纸张、画布、墨色、弱墨色、边框和分隔线
- 标题、正文、眉题、编号和目录字号
- 页面最大宽度、正文阅读宽度和段落行长
- Hero 高度、标题坐标、阅卷章位置和四格入口几何关系
- 目录宽度、正文列宽、卡片边框、阴影、圆角和间距节奏
- 桌面、平板和手机断点

学科主题通过最小 CSS 变量契约提供：

- `data-learning-subject="shenlun"`：申论蓝
- `data-learning-subject="interview"`：面试棕

现有 route tone 的橙、酸绿和红色不再控制八页的主视觉，只可作为局部内容提示色使用，且不得破坏申论/面试两套学科主色。

### 4.3 内容适配原则

共享抽象停止在“目录 + 正文表面”边界。以下内容继续由路由自己拥有：

- framework 的嵌套讲义、题型步骤器和文章内容
- 申论真题的筛选、题目行和参考方向
- 写作积累的静态入口、深层静态页面链接和按需数据加载
- 申论视频的档案卡和学习流程
- 面试页面的六张内容卡、四步流程和两张训练/复盘面板

## 5. 四个宏观章节

所有页面都声明恰好四个稳定的顶层章节。Hero 四格入口和左侧目录顶层项使用同一份声明；路由自己的次级条目保留在对应顶层章节之下。

| 页面 | 章节 01 | 章节 02 | 章节 03 | 章节 04 |
| --- | --- | --- | --- | --- |
| 申论·方法框架 | 表达规则 | 题型框架 | 核心能力 | 实用技巧 |
| 申论·真题精练 | 按年份看 | 按题型练 | 按主题复盘 | 真题索引 |
| 申论·写作积累 | 观点与热点 | 案例与论据 | 词语与修辞 | 作文与结构 |
| 申论·课程现场 | 课程精讲 | 课堂实录 | 工作日常 | 碎片分享 |
| 面试·题型方法 | 题型地图 | 训练流程 | 一题三遍 | 答后检查 |
| 面试·真题实战 | 真题地图 | 训练流程 | 当前索引 | 复盘清单 |
| 面试·表达训练 | 表达地图 | 四段训练 | 每日小练 | 回听重点 |
| 面试·课程现场 | 影像档案 | 观看流程 | 看课堂 | 课后笔记 |

写作积累现有八个入口继续全部保留，并分组如下：

- 观点与热点：热点时评、主题佳句、名人箴言
- 案例与论据：案例素材
- 词语与修辞：规范用词、比喻词库、对仗句库
- 作文与结构：作文框架

面试页面现有六张内容卡全部留在第一个“地图/档案”章节；四步流程进入第二章；两张 practice board 分别成为第三、第四章。四格宏观导航不截断、不删除六张内容卡。

## 6. 组件架构

### 6.1 数据模型

共享模型只描述页面结构，不描述正文内容：

```ts
type LearningSubject = 'shenlun' | 'interview';

type LearningMacroChapter = Readonly<{
  id: string;
  no: string;
  label: string;
  targetId: string;
  ariaLabel?: string;
}>;
```

每个路由提供四个 `LearningMacroChapter`。`id` 同时连接 Hero 入口、目录顶层项和正文目标；可见标签可以调整，但稳定 id 不随文案变化。

### 6.2 共享结构单元

建议形成以下边界，实施计划可以按现有命名习惯微调文件名，但职责不得合并回条件分支：

- `LearningPageFrame`：服务端友好的结构壳，组合顶部导航、Hero、章节区、正文布局和页脚插槽。
- `LearningHero`：只负责 topline、眉题、标题、说明、阅卷章和章节入口表面。
- `LearningChapterProvider`：客户端状态边界，持有当前宏观章节、IntersectionObserver、显式点击状态、移动端目录状态和过渡生命周期。
- `LearningHeroChapterStrip`：读取四章数据并触发 `activateChapter(id, sourceElement)`。
- `LearningMacroDirectory`：渲染四个顶层目录项，并接收路由提供的嵌套目录内容。
- `LearningManualLayout`：统一粘性目录、正文列和移动端目录抽屉的空间关系。
- `ShenlunShell` / `InterviewShell`：保留为轻量学科适配器，只提供学科主题、活动路由、Hero 元数据、章节声明和页脚链接顺序。

共享组件不得导入 framework manual、写作语料、题目数据、视频数据或面试内容组件。依赖方向只能是“路由内容传入共享框架”。

### 6.3 样式边界

新增或整理为两个窄共享层：

- 学习页结构/令牌样式：只包含八页共用的中性视觉和布局。
- 学习页过渡样式：只包含 root canvas 淡化、共享宏观章节元素移动和通用正文 settle 动画。

以下样式继续 route-scoped：

- framework 文章、题型、能力、技巧和嵌套目录样式
- writing 静态入口、热点、案例和文章样式
- interview 内容卡、流程和训练面板的专属细节

`menu-hierarchy-refinement.css` 默认继续由 framework/需要它的子树拥有。`framework-scene-transition.css` 只能拆出经过验证的通用片段，不能整体放入根布局。`tests/route-scope.test.mjs` 必须明确允许新的通用文件，同时继续阻止 specialist 文件泄漏。

## 7. Hero 到目录的过渡

### 7.1 桌面端

点击 Hero 章节入口后：

1. 入口进入 launching 状态，显示强调线和“进入”反馈。
2. 控制器确认 matching directory target 存在。
3. 在支持 View Transitions 且未开启减少动态效果时，当前入口和对应目录顶层项临时共享 `learning-chapter-shared` 身份。
4. 真正的活动章节和文档位置在 transition update 中完成；视觉上入口约用 0.7 秒移动、缩放到目录项。
5. 画布轻微淡化，正文在目录落位后淡入并上移少量距离。
6. 完成、失败或被新点击打断时，都在 `finally` 路径清理临时名称、root class、launching 和 arrival 状态。

同一时间只允许一对宏观入口和目录项拥有共享元素身份。快速连续点击采用“最后一次明确选择生效”，旧过渡必须清理，不能留下名称冲突或卡住的 launching 状态。

### 7.2 滚动观察

手动滚动正文时，IntersectionObserver 更新当前目录高亮。程序化进入章节期间暂时抑制被动观察结果，避免观察器和点击状态互相覆盖。观察器只更新活动状态，不反向触发 Hero 动画。

### 7.3 移动端

移动端不复制桌面的共享元素几何动画：

- 四格入口改为两列。
- 点击后定位到学习手册区域，打开目录抽屉并高亮对应顶层项。
- 目录抽屉关闭后，正文保持在可读位置。
- `Escape`、关闭按钮和 backdrop 都能关闭抽屉，并把焦点返回触发元素。
- 不允许抽屉造成横向溢出或焦点陷阱。

### 7.4 降级和错误处理

- `prefers-reduced-motion: reduce`：跳过 View Transition、平滑滚动和 settle 动画，直接更新状态与位置。
- 不支持 `document.startViewTransition`：使用相同的状态/定位逻辑即时进入章节，不抛错。
- 找不到目标目录项或正文目标：不启动动画，不改变当前活动章节；开发测试必须暴露错误映射。
- 浏览器 API 只能在客户端 effect/事件路径中读取，静态构建阶段不得访问 `document`、`window` 或 `matchMedia`。

## 8. 响应式与可访问性

### 桌面（大于 1024px）

- 左侧目录粘性定位，右侧正文保持参考页的中心阅读宽度。
- Hero、四格入口、阅卷章和标题坐标在八页一致。

### 平板（821–1024px）

- 保留双栏，缩窄目录与列间距。
- 卡片网格按内容类型降列，不压缩正文到不可读宽度。

### 手机（不大于 820px）

- Hero 进入正常文档流，四格入口两列排列。
- 左侧目录改为顶部目录按钮与抽屉。
- 题目行、内容卡、视频卡和 practice board 单列排列。
- 目标验证尺寸为 `390×844`。

所有章节入口使用原生按钮语义，支持 Tab 顺序、Enter/Space 激活和清晰 `:focus-visible`。显式激活与被动滚动必须区分，避免滚动观察时抢夺用户焦点。精确的焦点落点以实施前对现有 framework 行为的 characterization test 为准。

## 9. 测试与验收

### 9.1 先锁定行为

修改源代码前添加 characterization tests：

- 八个学习路由和两组路由关系不变。
- 当前 framework 四个 Hero 入口分别进入对应目录。
- desktop View Transition、unsupported fallback 和 reduced-motion 路径都能到达同一逻辑章节。
- transition 名称、root class、launching 和 arrival 状态在成功与失败后清理。
- 当前 specialist CSS/data imports 仍由原路由拥有。

### 9.2 结构与边界测试

- 八页各渲染四个唯一的宏观章节 id。
- 每个 Hero 入口恰好对应一个目录顶层项和一个正文目标。
- shared frame/Hero/controller 不导入任何 route-specialist 内容或数据。
- 写作八个入口、面试每页六张卡/四步流程/两张面板全部保留。
- 顶部跨页导航仍指向原八个 URL；Hero 四格只执行本页导航。
- 首页和代表性非核心路由不出现新的学习页 wrapper/class。

### 9.3 交互与无障碍测试

- 桌面四个入口可点击、可键盘激活，目录高亮和正文目标正确。
- 手动滚动只更新高亮，不递归触发过渡。
- 移动端目录可开关、无焦点陷阱，关闭后焦点返回。
- reduced-motion 下不依赖动画完成业务定位。
- 目标视口无横向溢出。

### 9.4 视觉与构建验收

每轮视觉修改后执行 `visual-verdict`，保存 verdict JSON，评分达到 90+ 才进入下一轮。至少覆盖：

- 参考页 `/shenlun/framework/`
- 复杂申论页 `/shenlun/questions/`
- 写作页 `/shenlun/writing/`
- 申论视频页 `/shenlun/videos/`
- 四个面试页
- 桌面 `1440×900` 与手机 `390×844`
- 动画开始、目录落位和移动端抽屉状态

最终必须通过：

- lint
- TypeScript 类型检查
- 全量 Node 测试
- 根路径静态构建
- Pages 路径静态构建

## 10. 实施顺序

1. 添加路由、结构、过渡、CSS 边界和内容保留的 characterization tests。
2. 提取共享中性令牌与结构组件，不改变任何路由视觉。
3. 抽象章节控制器，把 `/shenlun/framework/` 切到通用契约并证明行为不变。
4. 迁移结构最简单的 `/shenlun/videos/`，验证非讲义内容可以进入共享骨架。
5. 依次迁移 `/shenlun/questions/` 和 `/shenlun/writing/`，保护筛选、静态链接与数据边界。
6. 建立面试四章映射，逐页迁移四个面试页面并保留六卡/四步/双面板结构。
7. 在 Hero 和目录稳定后统一页脚结构。
8. 删除已无消费者的旧定位选择器和重复 Hero markup。
9. 完成八页桌面/移动视觉循环、全量验证和两种静态构建。

## 11. 主要风险与控制

- **共享壳膨胀：** 禁止按 route type 分支渲染正文，使用元数据和 ReactNode 插槽。
- **CSS 泄漏：** 只共享中性令牌和通用过渡，扩展 route-scope 测试而不是放松断言。
- **两个活动状态竞争：** Hero、目录和 IntersectionObserver 必须接入同一个章节状态源。
- **共享元素名称冲突：** 单次只绑定一个 source/target，并在所有结束路径清理。
- **动画成为正确性依赖：** 状态和定位先正确，动画只是 progressive enhancement。
- **四章与多内容项不匹配：** 允许顶层四章下面保留任意数量的路由专属次级项。
- **写作负载扩大：** shared frame 不导入任何写作语料，深层静态页与按分类加载保持原边界。
- **一次改八页难以定位回归：** 严格按参考页、简单申论页、其余申论、面试页的顺序迁移，每步验证。
- **静态构建失败：** 所有浏览器 API 留在客户端交互路径，并在关键阶段运行两种静态构建。

## 12. 完成定义

当且仅当以下条件全部满足，本轮实施才算完成：

- 八个核心学习页使用共享骨架并在视觉上属于同一系统。
- 申论蓝、面试棕和共用纸张体系正确。
- 四格 Hero 入口、目录、正文目标和共享元素过渡在八页可用。
- 原内容、链接、筛选、数据加载和深层路由没有损失。
- 首页及所有范围外路由未发生视觉或结构变化。
- 桌面和手机无横向溢出，键盘和 reduced-motion 路径可用。
- 每轮视觉评分达到 90+，最终 lint、类型、测试和两种静态构建全部通过。
