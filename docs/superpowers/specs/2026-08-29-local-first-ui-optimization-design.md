# 本地优先部署与全站 UI 优化设计

**状态：** 已确认  
**日期：** 2026-08-29  
**项目：** 答卷之外｜申论与面试学习站

## 1. 背景与现状

网站当前部署在 GitHub Pages，并保留 Tencent EdgeOne Pages 发布流程。远端仓库约 4.5 MB，Git 跟踪文件合计约 3.3 MB，最近一次 GitHub Pages 压缩产物约 7.3 MB。这些数字不属于异常的大型网站，因此本轮不通过删除学习内容或更换框架来“瘦身”。

当前需要解决的是四类问题：

1. 当前工作目录此前没有网站源码，日常开发依赖远端环境，缺少稳定的本地运行入口。
2. 全站链接、展开按钮、筛选器和普通内容使用了相近的视觉信号，学生难以判断哪些区域可以交互。
3. 根布局导入大量全站样式，内容数据和页面组件的边界不够稳定，不利于后续接入数据库和内容管理后台。
4. 首页音乐、歌词同步、移动端导航和多尺寸页面尚缺少统一、可重复的验收标准。

## 2. 目标

- 将完整源码和 Git 历史落到本地，以本地工作区作为日常编辑与验收入口。
- 提供 Windows 一键启动方式，同时支持同一局域网内的手机和平板访问。
- 保留 GitHub Pages 和 EdgeOne 的静态构建、发布能力。
- 保留现有纸张质感、宋体大标题、细线、主题色和滚动叙事，只做保守而系统的 UI 修补。
- 为页面链接、展开按钮、筛选器和普通内容建立互不混淆的交互语义。
- 覆盖首页、申论、面试、写作积累、题库、资料、工具和阅读页等全部现有路由。
- 在不删除学习内容的前提下，减少无关样式、数据和媒体的跨路由加载。
- 整理内容和浏览器练习记录的访问边界，为后续数据库与管理后台预留替换点。

## 3. 非目标

- 本轮不建设数据库、登录系统、权限系统或内容管理后台。
- 本轮不把 React/Vinext/Vite 改造成另一套前端框架。
- 本轮不删除现有文章、题目、案例、词库或课程栏目。
- 本轮不把本机开发端口直接暴露到公网。
- 本轮不改变 GitHub Pages 和 EdgeOne 的公开站点定位。

数据库、管理后台、学生数据跨设备同步、服务端备份属于后续独立项目。本轮只保证现有页面不直接依赖具体存储方式。

## 4. 已选方案

采用“本地优先、保留现有技术栈”的方案：

- 本地完整仓库是日常开发入口。
- Windows 启动脚本负责环境检查、启动开发服务器和显示本机/局域网地址。
- 同一 Wi-Fi 下的手机和平板通过局域网地址进行触摸和响应式验收。
- 本地 lint、静态构建和关键页面验收通过后，再由开发者决定是否推送到 GitHub。
- 推送到 `master` 后，现有 GitHub Actions 继续生成 GitHub Pages 与 EdgeOne 静态站。

未采用的方案：

- 仅下载 `site/` 静态产物：无法方便维护源码、热更新或长期演进。
- 改造成纯 Vite 静态站：当前产物体积很小，迁移收益不足以覆盖对既有路由和部署造成的风险。

## 5. 本地部署架构

### 5.1 单一源码，三条运行路径

1. **本机开发：** 使用 Windows 一键脚本启动带热更新的开发服务器。
2. **局域网验收：** 服务绑定可供局域网访问的地址，脚本打印可复制的手机访问 URL；不自动开放公网入口。
3. **可选公开发布：** 本地验证通过后推送，继续使用现有 GitHub Pages 和 EdgeOne 工作流。

### 5.2 启动脚本行为

启动脚本应：

- 检查 Node.js 是否满足项目要求（Node.js 22 或更高版本）。
- 检查 npm 是否可用。
- 在依赖缺失时使用锁文件安装依赖；依赖已存在时不重复安装。
- 让开发服务器监听局域网可访问的地址。
- 显示本机 URL 和可用的局域网 URL。
- 默认端口被占用时选择可用端口并明确显示最终地址。
- 不自动修改 Windows 防火墙；访问受阻时给出清晰提示。

`node_modules` 只存在本地并继续被 Git 忽略。它可能占用数百 MB，但不属于仓库或公开网站产物。

## 6. 面向未来的数据边界

本轮保持静态内容来源，但建立以下三层关系：

1. **内容数据：** 文章、题目、案例、词库和菜单使用稳定 ID 与一致类型。
2. **数据访问层：** 查询、筛选、分类、内容读取和浏览器练习记录通过集中函数访问。
3. **页面组件：** 页面只消费数据访问层返回的模型，不直接知道数据来自 TypeScript 文件、`localStorage` 还是未来 API。

浏览器练习记录需要继续兼容已有本地数据。读取失败时保留原始数据并回退到安全的空视图，不能在未确认兼容性时清空学生记录。

后续接入数据库时，以服务端 API 替换当前内容来源和本地记录实现；页面组件与路由结构不整体重写。

## 7. UI 与交互设计

### 7.1 视觉方向

采用“保守修补”：

- 保留纸张底色、宋体标题、酸绿/橙/蓝/紫灰主题色、细线分隔和现有品牌标识。
- 保留首页大标题与滚动氛围，但学习入口的识别优先于装饰元素。
- 阅读页减少高强度滚动和悬浮动效，优先保证连续阅读。
- 不把网站改造成传统后台、仪表盘或通用教育平台模板。

### 7.2 页面层级

全站使用稳定的四级顺序：

1. 全站导航；
2. 科目或栏目导航；
3. 当前页标题、简介和当前位置；
4. 内容、目录或学习工具。

移动端导航必须能打开、关闭和返回当前页；不得出现点击首页后空白、菜单遮挡正文或横向溢出。

### 7.3 四类交互语义

#### 页面链接

- 整行或整卡可点击。
- 使用主题色左侧导轨和右上 `↗` 箭头。
- 默认保持简洁；鼠标悬停、键盘聚焦或触摸激活时显示淡主题色背景。
- 使用真实链接元素，保留复制链接、浏览器历史和新标签页能力。

#### 展开按钮

- 明确显示“展开”或“收起”及方向符号。
- 使用按钮元素和持续可见的展开状态。
- 不使用 `↗`，避免与页面跳转混淆。

#### 筛选器与标签

- 选中状态持续可见，不仅依赖悬停。
- 鼠标、键盘和触摸产生相同的筛选结果。
- 搜索结果数量与空结果状态可见。

#### 普通内容

- 不使用 `↗`、手形光标、悬浮抬升、假按钮边框或点击阴影。
- 只通过排版、分隔和主题色表达内容层级。
- 比喻词库继续直接平铺展示并保留搜索，不恢复逐条展开。

## 8. 响应式设计

验收宽度覆盖：

- 360 px：较窄 Android 手机；
- 390 px：常见 iPhone；
- 430 px：较宽手机；
- 768 px：平板；
- 1440 px：桌面端。

移动端要求：

- 无横向溢出、遮挡或空白导航。
- 主要触摸区域约 44 px 或更大。
- 页面链接在无悬停环境下仍有清晰箭头和层级。
- 菜单打开后焦点、滚动和关闭行为可预测。
- 横竖屏切换后不保留错误宽度或不可见状态。

## 9. 体积与加载策略

### 9.1 基线与预算

- 远端仓库：约 4.5 MB。
- Git 跟踪文件：约 3.3 MB。
- 最近 Pages 压缩产物：约 7.3 MB。
- 本轮 UI 优化后的 Pages 压缩产物预算：不超过 8.5 MB；内容增长导致的增加必须在报告中单独说明。
- 当前约 1.4 MB 的分享图目标压缩到约 500 KB，同时保持 1200×630 尺寸和可接受的文字清晰度。

### 9.2 路由资源

- 基础变量、重置和通用控件样式保留为全局样式。
- 申论、面试、写作和文章阅读等路由专用样式移动到更接近对应路由的边界。
- 大型题库、案例、热点和词库数据不得进入不使用它们的页面包。
- 构建后生成路由 JS/CSS、图片和音频的独立体积报告。
- 不为追求数字而引入新的压缩依赖；优先使用现有工具和可验证的静态资源优化。

## 10. 音乐与歌词

首页保留音乐和歌词。用户选择的是预加载方案：

- 正常网络进入首页后预加载音频。
- 浏览器省流量模式下自动降为仅加载元数据。
- 仍需用户点击播放控件后才能播放，以符合浏览器自动播放限制。
- 播放、暂停、拖动进度、切到后台、恢复和播放结束都以音频元素真实 `currentTime` 为准。
- 歌词时间戳是唯一高亮依据，不使用独立动画计时器推测进度。
- 音频无法加载时停止歌词推进，显示可理解的错误和重试操作。
- 本地开发、GitHub Pages 子路径和 EdgeOne 根路径都使用可解析的同源音频地址。

## 11. 错误处理

### 11.1 自动恢复

- 默认端口占用时选择可用端口并显示新地址。
- 音频失败时保留播放器结构并提供重试。
- 图片失败时保留文字和布局，不留下空的可点击模块。
- 旧浏览器记录无法解析时保留原始数据并显示安全空状态。

### 11.2 阻断条件

- Node.js 版本不满足要求时停止启动并给出升级说明。
- 内容 ID 重复、静态路由缺失或数据读取失败时构建失败。
- lint、静态构建或关键页面检查失败时不得声明可以发布。
- 不自动修改系统防火墙或网络策略。

## 12. 验收与测试

### 12.1 自动检查

- 安装依赖后运行项目 lint。
- 运行静态构建，确认 GitHub Pages 和 EdgeOne 所需路径均生成。
- 建立现有路由清单，逐项检查输出文件和资源引用。
- 校验内容稳定 ID 的唯一性和必要字段。
- 校验歌词时间戳顺序与音频可用性。
- 记录构建前后产物、路由脚本、样式、图片和音频体积。

### 12.2 浏览器检查

- 在 360、390、430、768、1440 px 下检查首页和所有主要页面类型。
- 检查全站导航、栏目导航、页面链接、展开、筛选、搜索和返回路径。
- 检查键盘焦点、触摸点击区域、横竖屏和减少动画偏好。
- 检查音乐预加载、播放、暂停、进度拖动、后台恢复、结束和失败重试。
- 检查 GitHub Pages 子路径中的音频、图片、脚本和内部链接。
- 浏览器控制台不得保留已知的应用自身错误。

### 12.3 完成定义

本轮完成需要同时满足：

- 本地一键启动成功；
- 同一局域网手机可访问；
- 全部现有路由可达；
- 四类交互语义在全站一致；
- 多尺寸页面无已知遮挡、溢出或空白菜单；
- 音乐与歌词行为可重复验证；
- 静态构建通过并输出体积报告；
- GitHub Pages 与 EdgeOne 发布兼容性未被破坏；
- 没有已知的应用自身浏览器错误。

## 13. 风险与控制

- **大量全局 CSS 的顺序依赖：** 先用页面截图和关键交互锁定现有行为，再逐组移动样式；每组变更后重新构建与比较。
- **内容文件体积和类型不一致：** 先建立兼容当前数据的访问函数，再逐步统一类型；不一次性重写全部内容。
- **静态导出的路径差异：** 同时验证 GitHub Pages 子路径和 EdgeOne 根路径。
- **浏览器自动播放策略：** 预加载不等于自动播放，播放始终由用户操作触发。
- **局域网环境差异：** 脚本只显示地址和提示，不擅自修改防火墙。
- **未来后台范围膨胀：** 本轮只建立替换边界，不实现用户、权限、数据库或后台界面。
